# 演进史：从 DDD 到范式收敛

## 为什么需要了解这段历史

认知显化与决策驱动设计不是从零发明的。它经历了多次迭代和纠偏。了解这段历史有助于理解范式中的每个设计决策——尤其是"领域第一公民"这个最终收敛为什么如此重要。

## 七个阶段

```
Stage 1: DDD                           领域是核心（但未考虑 AI Agent）
    │
    ▼
Stage 2: CDD                           Agent 作为代码生成器
    │   "认知决定架构" — 丢失了领域
    ▼
Stage 3: 认知显化概念提出               纠正 CDD：认知应被显式管理
    │   "认知显化管道" 雏形
    ▼
Stage 4: 决策驱动概念的引入             扩展认知显化：不仅是理解，还要决策
    │   "认知 + 决策" 双路径
    ▼
Stage 5: "决策作为第一公民"             纠正 CDD：决策应被明确治理
    │   正确但有偏——把过程当成了目的
    ▼
Stage 6: "两类三种第一公民"             错误地把本体与过程并列
    │   产生类别错误
    ▼
Stage 7: "领域是第一公民"              最终收敛
    认知和决策是路径，本体是轮子
```

## 阶段详解

### Stage 1: DDD（传统）

DDD 是起点。它的核心贡献：
- 领域是软件的核心
- 统一语言（Ubiquitous Language）
- 战略设计（限界上下文）和战术设计（实体、值对象、聚合）

但 DDD 没有为 AI Agent 系统提供指导——它假设系统由确定性代码构成。

### Stage 2: CDD（代码驱动开发）

CDD 是 DDD 在 AI 时代的变体。它将 DDD 的"领域驱动"替换为"代码驱动"：

```
CDD 的假设：Agent 的主要活动是编码，所以编码过程就是领域过程。
CDD 的盲区：Agent 不仅是编码，更是理解、推理、决策。
```

### Stage 3: 认知显化

对 CDD 的纠偏：Agent 的核心是认知过程——上下文理解、推理、不确定性管理。这些应该被显式建模，而非隐式假设。

"认知显化"的概念由此诞生。

### Stage 4: 决策驱动

认知显化回答了"Agent 如何理解"，但没有回答"Agent 如何决定"。决策驱动补充了后半部分：每个认知输出都应经过系统化的决策流程。

### Stage 5: 决策作为第一公民

这一步纠正了 CDD 的根本偏向——但矫枉过正。它正确地指出了"决策应该是系统架构的一等关注点"，却错误地把"决策过程"当成了"系统存在的目的"。

### Stage 6: 两类三种（过程型 + 结构型）

试图解决第一公民的混淆，将本体纳入为"结构型第一公民"，认知和决策作为"过程型第一公民"。

**这是错误的一步**。它把本体和过程放在了同一维度比较，产生了类别错误——本体是领域的形式化表达（元层面），认知和决策是过程（操作层面），两者不可直接并列。

### Stage 7: 领域回归

最终收敛。认识到：
- 领域才是真正的第一公民
- 认知和决策是服务于领域的两条路径
- 本体是领域的形式化表达，是运行在路径上的轮子

## 各阶段的教训

| 阶段 | 教训 |
|:---|:---|
| CDD | 不要把过程当成目的 |
| 认知显化 | 理解需要显式建模 |
| 决策驱动 | 行动需要系统治理 |
| 决策作为第一公民 | 纠正偏向不等于新的真理 |
| 两类三种 | 不要混淆元层面和操作层面 |
| 领域回归 | 始终追问"系统为谁而建" |

## 对未来的启示

1. 范式收敛并不意味着探索的终结——领域第一公民的框架将指导我们更好地理解领域本身
2. 本体的工程实现是下一个重大挑战
3. 随着 AI Agent 系统的进化，范式定义可能需要再次修订——希望届时我们仍能记得"为谁而建"
