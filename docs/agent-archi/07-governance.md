# 治理与 Harness Engineering

## 元治理层

治理层是四层架构中的顶层，它的职责是**治理其他所有层的运行**。如果说认知路径负责"理解世界"、决策路径负责"改变世界"，那么治理层负责"确保理解和改变的过程正确且可控"。

```
治理层视角：
┌──────────────────────────────────────────┐
│  观察         约束          编排          │
│  ┌─────┐   ┌──────────┐   ┌─────────┐   │
│  │事件 │──►│ 状态机   │──►│ 工作流  │   │
│  │流   │   │ + 规则引擎│   │ 引擎    │   │
│  └─────┘   └──────────┘   └─────────┘   │
│                                          │
│      ↓ 事件驱动     ↑ 约束回馈           │
│                                          │
│  ┌──────────────────────────────────┐    │
│  │      编排器（Orchestrator）       │    │
│  │  ·循环控制（LLM ↔ 决策 循环）    │    │
│  │  ·Tool 调用生命周期管理          │    │
│  │  ·Sub-Agent 生命周期管理         │    │
│  │  ·人机交互协调                   │    │
│  └──────────────────────────────────┘    │
└──────────────────────────────────────────┘
```

## 事件驱动架构

治理层的基础是事件驱动。系统中的所有重要变化都产生事件：

```rust
enum SystemEvent {
    /// 认知路径事件
    Cognitive {
        phase: CognitivePhase,
        proposal_id: Uuid,
        status: CognitiveStatus,
    },
    /// 防火墙事件
    Firewall {
        layer: FirewallLayer,
        input_id: Uuid,
        result: FirewallResult,
    },
    /// 决策路径事件
    Decision {
        phase: DecisionPhase,
        proposal_id: Uuid,
        decision: Decision,
    },
    /// 工具调用事件
    Tool {
        tool_id: ToolId,
        status: ToolStatus,
        duration: Duration,
    },
    /// 异常事件
    Error {
        source: ComponentId,
        severity: ErrorSeverity,
        context: ErrorContext,
    },
}
```

事件流的特性：
- **不可变性**：事件一旦生成不可修改
- **有序性**：同一源的事件保持生成顺序
- **可追溯**：每个事件携带源标识和因果关系链
- **结构化**：事件类型由本体定义

## 状态机

治理层维护系统的全局状态机。状态机定义系统在什么状态下响应哪些事件：

```
          ┌──────────┐
          │  初始    │
          └────┬─────┘
               │
          ┌────▼─────┐
    ┌─────┤  认知中  ├─────┐
    │     └────┬─────┘     │
    │          │           │

    │     │  裁决中  │     │
    │     └────┬─────┘     │
```

## 约束系统

治理层的约束系统对下层施加限制：

| 约束类型 | 作用范围 | 示例 |
|:---|:---|:---|
| 速率约束 | 认知层 | 每轮最多 3 个 Tool 调用 |
| 时间约束 | 决策层 | 裁决必须在 5 秒内完成 |
| 资源约束 | 全系统 | 最多同时 10 个 Sub-Agent |
| 安全约束 | 全系统 | 敏感操作需人类确认 |
| 语义约束 | 防火墙 | 引用类型必须在注册表中 |

## Harness Engineering

治理层的工程实践称为 **Harness Engineering**。它包含五个核心关注点：

| 领域 | 说明 | 关键机制 |
|:---|:---|:---|
| 编排 | 控制认知-决策循环 | Loop Engine |
| 工具治理 | 管理 Tool 注册、调用、安全 | Tool Registry |
| 分层记忆 | 短期/长期/工作记忆管理 | Memory Store |
| 可观测性 | 事件记录、追踪、指标 | Observability |
| 自适应进化 | 系统根据历史改进自身 | Evolution Engine |

## 治理层与领域第一公民

治理层虽然是"顶层"，但它仍然服从领域第一公民原则：
- 状态机的状态定义来自领域流程
- 约束的阈值来自领域需求
- 编排策略来自领域优先级
- 记忆管理策略来自领域信息的价值判断
