# 本体轮子

## 领域的形式化语义基础设施

本体是本范式中最独特的设计元素。它不是系统中被治理的对象（那是领域），也不是治理过程的一部分（那是认知路径和决策路径），而是**确保前两者有效运作的语义基础设施**。

类比：领域是系统要服务的地理空间（领土），认知和决策是通往那里的路径（道路），本体是让路径在语义上可行的轮子（行走机构）。

## 类型注册表

类型注册表是本体最基础的部分。它定义了系统中所有领域类型的规范：

```rust
struct TypeRegistry {
    /// 实体类型
    entities: HashMap<TypeId, EntityDef>,
    /// 值类型
    values: HashMap<TypeId, ValueDef>,
    /// Action 类型
    actions: HashMap<TypeId, ActionDef>,
}

struct EntityDef {
    /// 唯一标识
    id: TypeId,
    /// 字段定义
    fields: Vec<FieldDef>,
    /// 不变约束
    invariants: Vec<Constraint>,
    /// 父类型（支持继承）
    extends: Option<TypeId>,
}

struct ActionDef {
    /// Action 名称
    name: String,
    /// 输入参数 Schema
    input_schema: JsonSchema,
    /// 输出类型
    output_type: TypeId,
    /// 可执行条件
    preconditions: Vec<Constraint>,
    /// 副作用声明
    effects: Vec<Effect>,
}
```

## 约束公理

约束公理是本体中的"法律"。所有通过语义防火墙的提案、所有决策层的裁决，都必须满足这些约束：

| 约束类型 | 示例 | 级别 |
|:---|:---|:---|
| 类型约束 | "金额字段必须为数字" | 硬约束 |
| 范围约束 | "年龄在 0-150 之间" | 硬约束 |
| 业务约束 | "订单金额必须大于 0" | 硬约束 |
| 上下文约束 | "只有管理员可以删除用户" | 硬约束 |
| 建议约束 | "建议使用标准地址格式" | 软约束 |

## 本体与四层架构

```
认知层      →   使用本体：上下文构建（从本体获取领域知识）
               产出：结构化提案（意图类型由本体定义）

语义防火墙  →   使用本体：Parsing（类型定义）
               Validation（约束公理）
               Normalization（映射表）

决策层      →   使用本体：裁决依据（领域约束）
               产出：审计记录（类型由本体定义）

治理层      →   使用本体：事件 Schema
               约束本体变更本身
```

## 本体的演化

本体不是静态的。领域演化时，本体也必须演化：

- **向前兼容**：新增类型和字段不破坏现有系统
- **版本化**：每个本体版本可独立引用和测试
- **迁移策略**：旧本体实例到新本体的自动迁移
- **影响分析**：本体变更影响的组件自动识别

## 本体 vs 传统 Schema 定义

| 维度 | 传统 Schema | 本体 |
|:---|:---|:---|
| 焦点 | 数据格式 | 领域语义 |
| 约束 | 类型 + 格式 | 类型 + 范围 + 业务规则 + 上下文 |
| 演化 | 不兼容变更 | 向前兼容优先 |
| 消费方 | 序列化/反序列化 | Parser + Validator + Normalizer |
| 生命周期 | 静态 | 与领域同步演化 |
