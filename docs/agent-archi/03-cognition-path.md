# 认知显化路径

## 从概率到结构的转化

LLM 的本质是一个概率生成器：给定上下文，输出最可能的 Token 序列。认知显化路径的目标是：**将这个概率输出转化为结构化认知，作为决策路径的输入。**

```
LLM 概率输出            结构化认知
    │                       ▲
    │   认知显化管道         │
    │   ┌───────────┐       │
    ├──► 上下文构建  ├───────┤
    │   └───────────┘       │
    │   ┌───────────┐       │
    ├──► 提示词管理  ├───────┤
    │   └───────────┘       │
    │   ┌───────────┐       │
    └──► 不确定性管理├───────┘
        └───────────┘
```

## 上下文构建

上下文构建是认知路径的起点。它回答：**当前认知需要哪些信息？**

| 上下文来源 | 说明 | 治理要求 |
|:---|:---|:---|
| 系统提示 | 角色定义、行为边界 | 版本化，审计 |
| 会话历史 | 当前对话的完整记录 | 有损压缩策略 |
| 领域知识 | 本体定义、约束规则 | 按需加载，本体驱动 |
| 工具定义 | 可用工具的描述 | 本体生成 |
| 执行反馈 | 上一次行动的结果 | 事实性校验 |

## 提示词管理

提示词管理解决的是：**如何组织上下文使得 LLM 产生符合领域预期的输出？**

关键原则：
- **最小化提示**：只给 LLM 完成任务所需的最少信息，减少噪声
- **结构化提示**：提示词应使用结构化格式（Markdown、JSONSchema）而非自由文本
- **角色分离**：系统角色 vs 用户角色的职责明确分离
- **版本追踪**：每个提示模板应有版本号和变更记录

## 不确定性管理

LLM 的概率本质意味着输出天生具有不确定性。不确定性管理承认并处理这一现实：

| 不确定性类型 | 来源 | 处理策略 |
|:---|:---|:---|
| 语义不确定 | LLM 对同一输入的不同理解 | 本体约束 + 多候选裁决 |
| 结构不确定 | LLM 输出格式偏差 | 语义防火墙 Parsing 层 |
| 事实不确定 | LLM 幻觉 | 知识图谱校验 |
| 策略不确定 | 多种可行方案 | 决策路径裁决 |

## 显化输出

认知显化的输出是结构化认知提案（Cognitive Proposal）：

```rust
struct CognitiveProposal {
    /// 提案的唯一标识
    proposal_id: Uuid,
    /// 提案的语义意图（从本体中选取）
    intent: IntentType,
    /// 提案内容，结构化数据
    content: serde_json::Value,
    /// LLM 对提案的置信度
    confidence: f64,
    /// 多个候选方案（不确定性管理的产物）
    alternatives: Vec<Alternative>,
    /// 来源追踪
    trace: Vec<CognitiveTrace>,
}
```

这个提案将作为输入传递给语义防火墙，由防火墙完成结构校验和语义规范化，然后提交到决策路径进行裁决和执行。

## 认知路径与领域的关系

认知路径是**服务于领域**的：
- 上下文构建从领域本体中获取所需知识
- 提示词管理使用领域语言组织提示
- 不确定性管理的校验标准来自领域约束
- 结构化提案的意图类型由领域本体定义
