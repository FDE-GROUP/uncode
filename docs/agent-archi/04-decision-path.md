# 决策驱动路径

## 从认知到行动的治理闭环

决策路径接收从认知路径经过语义防火墙处理后的确定性提案，完成从认知到行动的转化。它的核心职责是：**将可能性转化为确定性，将提议转化为执行。**

```
结构化提案                  确定性行动
    │                          ▲
    │   决策管道                │
    │   ┌──────────┐           │
    ├──► 提案接收  ├───────────┤
    │   └────┬─────┘           │
    │        ▼                 │
    │   ┌──────────┐           │
    │   │  裁决    ├───────────┤
    │   └────┬─────┘           │
    │        ▼                 │
    │   ┌──────────┐           │
    │   │  执行    ├───────────┤
    │   └────┬─────┘           │
    │        ▼                 │
    │   ┌──────────┐           │
    │   │  审计    ├───────────┤
    │   └──────────┘           │
    │                          │
    │   每个阶段产生事件        │
    │   事件 → 治理层观察      │
    │   治理层 → 约束决策       │
    └──────────────────────────┘
```

## 提案接收

提案接收是决策管线的入口。它接收来自语义防火墙的规范提案，执行以下检查：

| 检查项 | 说明 | 失败处理 |
|:---|:---|:---|
| 完整性 | 提案包含所有必要字段 | 回退到认知路径重新生成 |
| 一致性 | 提案内容与意图类型匹配 | 交由异常裁决处理 |
| 时效性 | 提案在有效时间窗口内 | 超时则丢弃 |
| 权限 | 发起方有权提出此类提案 | 拒绝并记录审计事件 |

## 裁决

裁决是决策路径的核心。它回答：**这个提案应该被执行吗？**

裁决支持多种策略：

| 策略 | 适用场景 | 说明 |
|:---|:---|:---|
| 单路径裁决 | 简单、确定的提案 | 满足约束即通过 |
| 多路径裁决 | 多个候选方案 | 选择最优方案 |
| 人机协作裁决 | 高风险决策 | 需要人类审批 |
| 共识裁决 | 多方协作 | 多个 Agent 达成一致 |

裁决依据来自以下层级（优先级从高到低）：

1. **领域约束**：硬性规则，不可违背
2. **治理策略**：编排层配置的策略规则
3. **历史模式**：基于过往决策的经验学习
4. **LLM 置信度**：认知路径提供的置信度评分

## 执行

执行将裁决通过的提案转化为具体的系统行动：

```rust
enum ExecutedAction {
    /// 调用工具
    ToolInvocation {
        tool: ToolId,
        args: serde_json::Value,
    },
    /// 更新认知上下文
    ContextUpdate {
        delta: ContextDelta,
    },
    /// 与用户交互
    UserInteraction {
        message: String,
        options: Vec<ResponseOption>,
    },
    /// 触发子 Agent
    SubAgentSpawn {
        agent: AgentId,
        task: TaskSpec,
    },
}
```

执行阶段的关键要求：
- **幂等性**：同一提案的多次执行应产生相同效果（或可安全重试）
- **可观测性**：每个执行步骤产生事件，供治理层记录和分析
- **可中断性**：支持在执行过程中取消或修改

## 审计

审计确保每个决策可追踪：

```rust
struct DecisionRecord {
    decision_id: Uuid,
    proposal_id: Uuid,
    adjudicator: AdjudicatorId,
    decision: Decision,
    reason: String,
    evidence: Vec<Evidence>,
    timestamp: DateTime<Utc>,
}
```

审计记录永不删除，支持：
- 事后的决策回溯分析
- 作为未来决策的参考案例
- 合规性审查

## 事件流

决策路径的每个阶段产生事件，形成完整的事件流：

```
提案接收事件 → 裁决事件 → 执行事件 → 审计事件
    │            │         │          │
    └────────────┴─────────┴──────────┘
                      │
                      ▼
              治理层事件处理器
              状态机更新·约束检查·日志记录
```

这些事件构成治理层的输入，治理层通过观察和约束形成决策路径的监督闭环。
