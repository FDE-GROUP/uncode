# 语义防火墙

## 连接认知与决策的三层管线

语义防火墙是认知路径与决策路径之间的关键边界。它将 LLM 的概率性输出转化为决策层可处理的确定性结构。

```
认知路径输出（概率性）
    │
    ▼
┌─────────────────────┐
│   Parsing（解析）    │
│   文本 → 结构        │
│   格式校验           │
│   类型匹配           │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│  Validation（验证）  │
│   语义验证           │
│   约束检查           │
│   领域规则           │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│ Normalization（规约）│
│   字段规约           │
│   默认值填充         │
│   引用解析           │
└────────┬────────────┘
         ▼
决策路径输入（确定性）
```

## Parsing 层

Parsing 层负责将 LLM 输出的文本/半结构化数据转化为强类型结构。

| 输入类型 | Parsing 策略 | 失败处理 |
|:---|:---|:---|
| JSON 格式 | serde_json 反序列化 | 结构修复 → 重新解析 |
| Markdown 结构 | 正则/模式匹配提取 | 降级为文本解析 |
| 代码块 | 语言检测 + 语法解析 | 回退提示词重新生成 |
| 自由文本 | 意图分类 + 槽位填充 | 标记低置信度提交裁决 |

Parsing 输出是弱类型结构——格式正确，但语义尚未验证。

## Validation 层

Validation 层在 Parsing 的基础上执行语义验证。它回答：**这个结构在领域语义中是否有效？**

验证维度：
- **类型正确性**：字段值是否匹配声明的类型
- **范围约束**：值是否在领域允许的范围内
- **引用完整性**：引用的实体是否存在
- **业务规则**：是否违反领域业务约束
- **本体一致性**：是否与当前本体定义一致

Validation 的校验标准来自本体。没有本体，Validation 只能做通用格式校验，无法做领域语义验证。

## Normalization 层

Normalization 层对验证通过的提案进行规范化处理：

```rust
struct NormalizedProposal {
    /// 原始提案 ID（用于追踪）
    original_id: Uuid,
    /// 规约后的规范字段
    normalized_fields: Vec<NormalizedField>,
    /// 填充的默认值记录
    defaults_applied: Vec<DefaultRecord>,
    /// 引用解析结果
    resolved_references: Vec<ReferenceResolution>,
    /// 规约过程日志
    normalization_log: Vec<NormalizationStep>,
}
```

Normalization 的核心操作：
1. **字段规约**：将同义不同名的字段统一为规范名称
2. **默认值填充**：未提供的可选字段使用本体定义的默认值
3. **引用解析**：将逻辑引用解析为物理 ID
4. **单位转换**：统一度量单位
5. **格式统一**：日期、金额等格式统一化

## 防火墙的不确定性处理

防火墙本身不产生不确定性，但它需要处理认知路径传递的不确定性：

| 场景 | 处理策略 |
|:---|:---|
| Parsing 模糊 | 保留多个 Parsing 候选，提交裁决 |
| Validation 告警 | 软约束告警通过，硬约束拒绝 |
| Normalization 歧义 | 选择最常见映射，标记审计 |
| 整体低置信度 | 回退到认知路径重新生成 |

## 防火墙与本体

防火墙是对本体最密集的消费者：
- Parsing 使用类型定义指导反序列化
- Validation 使用约束公理验证语义
- Normalization 使用映射表执行字段规约

没有本体，防火墙退化为简单的格式校验器——这是当前许多 Agent 系统的实际状态。
