# uncode TUI 交互设计详案

## 一、设计目标

uncode TUI 是一款以**技术人员为第一用户**的终端 AI Agent 工作界面。设计核心：

| 原则 | 实现 |
|------|------|
| 技术人员优先 | 默认完整四面板视图，信息密度匹配 IDE/tmux |
| 非程序员友好 | `/simple` 一键切换简化双面板视图 |
| 过程可见 | 四个面板各自反映 Agent 工作的一个维度 |
| 渐进披露 | 代码细节按需展开，默认只展示自然语言描述 |

### 2.3 代码细节视图（快捷键 `Ctrl+D` 切换）

按需展开，覆盖在右侧面板区域，展示：
- 代码 diff（增删行高亮）
- 语法高亮（tree-sitter）
- 文件路径和行号

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+D` | 切换代码细节视图 |
| `Ctrl+E` | 展开/折叠当前面板到全屏 |
| `Ctrl+L` | 锁定/解锁面板布局（禁用自适应切换） |
| `Tab` | 切换面板焦点 |
| `/simple` | 切换到简化视图 |
| `/full` | 恢复到完整四面板视图 |

## 三、面板详细设计

### 3.1 任务清单面板（TaskList）

**位置：** 默认左上，简化视图独占上半

**数据源：** `TaskUpdate` 事件

**任务状态：**

| 图标 | 状态 | 含义 |
|------|------|------|
| ⏳ | Pending | 待执行 |
| 🔄 | Running | 正在执行 |
| ✅ | Done | 已完成 |
| ❌ | Failed | 失败（可重试） |
| 🚫 | Blocked | 受阻（等待前置任务） |

**交互：**
- `↑/↓` 浏览任务
- `Enter` 展开任务详情（关联的工具调用记录）
- `r` 重试失败任务
- `p` 调整任务优先级（上移/下移）
- `d` 删除任务

**空状态：** Agent 尚未规划任务时显示提示："描述你的需求，Agent 会自动拆解为任务清单"

**订阅的事件：**
```
TaskUpdate { task_id, status, title, subtasks, depends_on }
```

---

### 3.2 工具调用面板（ToolCalls）

**位置：** 默认右上，简化视图隐藏

**数据源：** `ToolCallStart` / `ToolCallProgress` / `ToolCallEnd` 事件

**工具列表显示：**

```
🛠️ 工具调用
────────────────────────────────────────
  ✅ read   src/main.rs           (12ms)
  ✅ grep   "fn login"            (8ms)
  🔄 write  src/auth.rs           (writing...)
  ⏳ bash   cargo test            (pending)
────────────────────────────────────────
```

**进度指示形态：**

| 工具类型 | 进度形态 |
|---------|---------|
| read / grep / find | 即时完成，显示执行时间 |
| write / edit | 显示字节数 |
| bash（短命令，<5s） | Spinner `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` |
| bash（长命令） | 实时滚动输出日志（最近 10 行） |
| web_fetch | 带百分比的进度条 `[██████░░░░] 60%` |

**交互：**
- `Enter` 展开工具调用结果（查看完整输出）
- `Ctrl+C` 取消正在执行的工具调用
- `r` 重新执行最近一次失败的工具调用

**空状态：** Agent 尚未调用工具时显示："等待 Agent 开始工作..."

**订阅的事件：**
```
ToolCallStart    { tool_id, tool_name, arguments_summary }
ToolCallProgress { tool_id, progress_type, detail }
ToolCallEnd      { tool_id, status, duration_ms, output_size }
```

---

### 3.3 思考过程面板（Thinking）

**位置：** 默认左下，简化视图隐藏

**数据源：** `ContentDelta` 事件

**双视图模式：**

| 模式 | 用户 | 显示内容 |
|------|------|---------|
| 技术视图（默认） | 软件工程师 | LLM 原始推理链，包含代码分析和技术决策 |
| 自然语言视图（`/think simple`） | 非程序员 | 提炼后的要点列表，去掉技术术语 |

**消息渲染：**
- Markdown 渲染（pulldown-cmark）
- 代码块语法高亮（tree-sitter）
- 实时流式追加（打字效果）

**交互：**
- `↑/↓` / `PageUp/PageDown` 滚动查看历史思考过程
- `/think simple` 切换到自然语言提炼视图
- `/think full` 恢复到完整技术视图

**空状态：** "等待 Agent 开始思考..."

**订阅的事件：**
```
ContentDelta { delta_type: "thinking" | "text", content }
```

---

### 3.4 阶段总结面板（Summary）

**位置：** 默认右下，简化视图独占下半

**数据源：** `PhaseSummary` 事件

**总结格式：**

```
📝 阶段总结 — 第 2 轮
────────────────────────────────────────
已完成：
  ✅ 分析了项目结构（3 个 crate，15 个源文件）
  ✅ 理解了认证流程（JWT + middleware 模式）
  ✅ 实现了 src/auth.rs 中的登录接口

产生的问题：
  ⚠️ 测试文件缺失，需要补充

下一步计划：
  ⏳ 编写 auth 模块的单元测试
  ⏳ 更新配置文件中的 JWT 密钥
  ⏳ 验证端到端登录流程

Token 消耗：输入 2,340 / 输出 890
────────────────────────────────────────
```

**交互：**
- 用户确认：输入 `ok` 或 `y` 继续下一阶段
- 用户调整：输入自然语言修改下一步计划
- 用户暂停：输入 `pause` 暂停 Agent 执行

**空状态：** "完成第一个任务后会自动生成阶段总结..."

**订阅的事件：**
```
PhaseSummary { phase, completed, issues, next_steps, token_usage }
```

## 四、全局交互状态

### 4.1 错误状态

当发生错误时（LLM 调用失败、工具执行异常），底部状态栏显示错误摘要：

```
⚠️ 错误：LLM 请求超时（GLM API 无响应）  [r:重试] [c:切换供应商] [h:帮助]
```

| 错误类型 | 用户看到 | 可用操作 |
|---------|---------|---------|
| LLM API 超时 | "请求超时，正在重试..." | 重试 / 切换供应商 / 帮助 |
| LLM 认证失败 | "API 密钥无效，请执行 /config 配置" | 打开配置 |
| 工具执行失败 | "bash 命令执行失败（退出码 1）+ 错误摘要" | 查看详情 / 重试 |
| 网络断开 | "网络连接中断，等待恢复..." | 离线模式（仅本地工具） |

### 4.2 会话状态

顶部状态栏：

```
uncode v0.1  |  会话: #42-20260514  |  模型: DeepSeek-V3  |  Token: 12.3k  |  运行时间: 23m
```

### 4.3 空面板状态

每个面板在无数据时显示引导性提示，而非空白：

| 面板 | 空状态提示 |
|------|-----------|
| 任务清单 | "描述你的需求，Agent 会自动拆解为任务清单" |
| 工具调用 | "等待 Agent 开始工作..." |
| 思考过程 | "等待 Agent 开始思考..." |
| 阶段总结 | "完成第一个任务后会自动生成阶段总结..." |

## 五、事件流与面板映射

Agent 通过事件流驱动四个面板的更新：

```
Agent ──TaskUpdate──────→ 任务清单面板
Agent ──ContentDelta────→ 思考过程面板
Agent ──ToolCallStart───→ 工具调用面板
Agent ──ToolCallProgress→ 工具调用面板
Agent ──ToolCallEnd─────→ 工具调用面板
Agent ──PhaseSummary────→ 阶段总结面板
Agent ──Error───────────→ 全局错误通知
```

所有面板共享同一个事件总线，各自过滤订阅的事件类型。

## 六、技术实现

### 6.1 框架选型

| 组件 | 技术 |
|------|------|
| 终端渲染 | ratatui + crossterm |
| 语法高亮 | tree-sitter（10 种语言） |
| Markdown 渲染 | pulldown-cmark |
| 异步事件 | tokio::sync::broadcast |
| 输入处理 | crossterm event + 自定义 input parser |

### 6.2 渲染策略

- 增量渲染：仅重绘收到事件更新的面板
- 默认刷新率：60fps（终端兼容的前提下）
- 长文本截断：面板内文本自动截断，展开后完整显示
- 自适应终端尺寸：面板比例根据终端宽度动态调整（最小 80x24）

### 6.3 输入编辑器

底部命令行输入区支持：
- 多行输入（`Alt+Enter` 换行）
- Tab 补全（文件路径、斜杠命令）
- 历史命令（`↑/↓` 浏览）
- Emacs 风格行编辑（`Ctrl+A/E/K/U`）
- 粘贴检测（大段文本自动确认）
